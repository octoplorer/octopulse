## 通用配置

通用配置按类型提供适用项。主动可用性检查指 HTTP(S)、TCP、DNS；被动心跳与证书风险不套用其故障确认阈值。

- 显示名称、备注、标签、分组、启用/暂停。
- 周期性主动探测的检查间隔、探测预算与超时；被动心跳配置独立的预期周期及宽限。
- 主动可用性检查的轮次内追加重试次数、重试等待、连续失败阈值、连续成功恢复阈值。
- 选择已有通知渠道、恢复通知开关、持续故障提醒间隔。
- 时区与维护计划、手动检查、诊断结果查看。

主动可用性检查的重试 2 次、失败阈值 1、恢复阈值 1 已确认。所有 HTTP 请求方法采用相同的追加重试规则和默认值，平台不根据方法名称推断可重复调用性或调整次数；配置者负责选择适合重复探测的请求。心跳超期和证书风险使用各自已确认的状态判定。

当前默认值与校验边界见 [配置模型](../internal/domain/monitor.go)；创建接口提供默认追加重试 2 次，显式配置为 0 时不追加重试。

| 配置                        | 当前默认值与范围                                             |
| --------------------------- | ------------------------------------------------------------ |
| HTTP(S)、TCP、DNS 检查间隔  | 默认 60 秒，30 秒–30 天                                      |
| 证书检查间隔                | 默认 1 天，30 秒–30 天                                       |
| 主动探测单次尝试超时        | 默认 10 秒，1 秒至检查间隔                                   |
| 主动探测整轮预算            | 使用检查间隔限制整轮执行，包含追加重试及等待，并预留提交时间 |
| 主动探测追加重试            | 默认 2 次，0–10 次；重试等待为 0 秒至检查间隔                |
| 主动可用性故障/恢复确认阈值 | 均默认 1 次，1–100 次                                        |
| 持续故障提醒间隔            | 默认 0（关闭）；开启时至少 30 秒                             |
| 被动心跳预期周期与宽限      | 预期周期默认 60 秒、至少 30 秒；宽限默认 0 秒、不得为负      |

主动探测的检查间隔用于调度 HTTP(S)、TCP、DNS 和证书探测；心跳不按该间隔发起探测或追加重试，超期判断使用自己的预期周期和宽限。主动可用性的故障/恢复确认阈值不用于心跳或证书风险判定。

## HTTP(S)

| 设置组     | 已确认首版范围                                                                                                |
| ---------- | ------------------------------------------------------------------------------------------------------------- |
| 请求目标   | URL、查询参数、方法、重复请求头、Host 覆盖                                                                    |
| 请求体格式 | 无请求体、JSON、URL 编码表单、multipart 字段/文件、文本、原始字节                                             |
| 字符编码   | 默认 UTF-8；文本/表单可选常见非 UTF-8 编码；JSON 使用 UTF-8                                                   |
| 传输压缩   | 独立管理 Accept-Encoding 与解压；支持 gzip；断言针对解压及字符解码后的内容                                    |
| 认证       | Basic、Bearer、API Key/自定义认证头；引用、替换秘密而不回读明文                                               |
| TLS        | 默认验证证书、明确开关、自定义 CA、PEM 客户端证书与私钥（mTLS）、SNI、TLS 版本范围                            |
| 连接       | HTTP(S)/SOCKS 代理及其认证、自定义 DNS、固定连接 IP；保留目标 Host/SNI 语义，说明代理下的解析方式             |
| 重定向     | 开关、最大跳数（默认 5，范围 1–20）、目标范围；处理方法变化及凭据转发规则                                     |
| 成功断言   | 状态码集合/区间、响应头、文本包含/不包含、正则、JSON 字段值、响应时间上限；全部已启用断言通过才算成功         |
| 限制与诊断 | 解压后大小限制（默认 2 MiB，范围 1 byte–16 MiB）、最终 URL、状态码、实际尝试数、总延迟、连接/TLS/首字节等诊断 |

“请求体格式”“字符编码”“HTTP 传输压缩”是不同设置。Multipart 的 boundary 和 Content-Type 由构造器管理，不能要求用户同时手写一个可能冲突的 boundary。

平台不会为 POST/PATCH 等方法单独禁用追加重试，也不会自行生成或要求幂等键。用户仍可通过自定义请求头提供任何目标所需字段。一次平台探测尝试可能包含重定向和标准 HTTP Transport 的透明网络处理，不应把底层所有网络请求混同为平台追加重试次数。

## 其他首版类型

| 类型     | 已确认首版范围                                                                                                               |
| -------- | ---------------------------------------------------------------------------------------------------------------------------- |
| TCP      | 主机/端口、连接成功断言；可选 TLS、发送文本/字节及接收文本/正则断言；超时与接收大小限制（默认 64 KiB，范围 1 byte–16 MiB）   |
| DNS      | 查询域名、记录类型、指定解析服务器及端口、UDP/TCP、期望响应码与记录值断言；A/AAAA/CNAME/MX/TXT/NS/SRV/PTR/SOA/CAA 等常用类型 |
| 被动心跳 | 可轮换的独立密钥、预期周期、宽限、成功/失败上报、可选描述；首次 Unknown、超期 Down、成功 Up 已确认                           |
| 证书到期 | TLS 主机/端口、SNI、CA/证书校验选项、默认每日检查、可配置提醒阈值；四态及不计服务可用率已确认                                |

## 后续范围

Digest、OAuth2 自动刷新、PKCS#12、Brotli、DNSSEC/DoH/DoT、脚本断言，以及 ICMP/WebSocket/gRPC/数据库探测不纳入已确认首版范围。增加这些能力前再核实其依赖和产品语义。

## 已核实的实现事实

- 当前调度器按检查间隔设置整轮 context deadline，包含追加重试及等待，并在截止前预留 100 ms 提交时间；单次探测另按 `timeoutSeconds` 限制，且不会超过整轮剩余预算。[调度轮次](../internal/engine/engine.go)、[单次探测](../internal/probe/probe.go)
- 301/302/303 可能改变请求方法，307/308 保留可重放请求体；当前重定向策略按开关、最大跳数和目标范围执行，跨源时移除认证及带秘密引用的头。[HTTP 探测实现](../internal/probe/http.go)
- Transport 具有有限透明网络重试；平台追加重试是另一层行为。[Transport 源码](https://go.dev/src/net/http/transport.go)
- 自动 gzip 解压与用户手动指定 Accept-Encoding 的行为不同，不能依赖一条未经统一处理的默认分支。[Transport](https://pkg.go.dev/net/http#Transport)
- CA、mTLS、SNI 和 TLS 版本可通过标准库配置。[TLS Config](https://pkg.go.dev/crypto/tls#Config)
- 非 UTF-8 转码需要显式处理，net/http 不自动转换字符集。[Go 字符转换](https://pkg.go.dev/golang.org/x/text/encoding)

当前实现采用 miekg/dns、Go 标准 HTTP/TLS 传输及 golang.org/x/text 转码，固定依赖版本以 [go.mod](../go.mod) 和 `go.sum` 为准。首版实施阶段记录了 DNS 常用记录类型和 UDP 截断转 TCP 的真实 socket 用例通过结果，本轮文档核对未重跑该套件。JSON 字段断言采用 RFC 6901 JSON Pointer。字符集白名单为 UTF-8、ISO-8859-1、Windows-1252、GBK、GB18030、Shift_JIS、Big5，JSON 限 UTF-8。具体边界及测试名称见 [验收映射](acceptance.md)。
