# Octopulse 首版规格与验收

状态：Q1–Q26 已回答；Q20、Q24 按用户修正执行，最新决定移除首版 GitHub 主题。产品分支已收敛，整体规格待最终确认，尚未开始实现。

本规格集中已确认产品决定和明确标注的工程默认方案。具体工具版本、数据访问库、限值和目录布局由实现阶段核实并固定，不继续把常规工程选型变成产品问卷。

## 产品与运行边界

- 单组织自托管，多人账号；首版单 Go 服务实例，不提供分布式探针或多实例调度。
- 容量目标为 100 个监控项、主动检查最小 30 秒，须压测验证，不代表已达到的性能。
- Go 承担 API、探测、调度、历史统计、通知、页面发布和 Beszel 适配。Node.js 仅用于前端和契约构建。
- mise 固定 Go、Node.js、aube 与开发任务；aube 管理前端依赖，工具锁文件和包锁文件分别维护。
- SQLite 与 PostgreSQL 均可配置使用，保持相同业务语义；SQLite 作为拟采用的自托管默认值。迁移、备份恢复和关键集成流程分别验证；工程细节见 [双数据库方案](./database-design.md)，其中工具与参数仍为拟采用方案。
- 拟采用二进制与 Docker 交付；运行数据与平台管理的页面图片资源持久化。内网探测和自定义代理是正常自托管能力。
- 未获用户要求前，不 commit、不 push；之后获授权时使用 Conventional 风格。

## 前端与契约

- 管理后台和状态页使用 Vite + Vue 纯 CSR SPA，Vue Router、VueUse 和 Pinia Colada 简化路由、浏览器状态与服务端数据缓存。
- UnoCSS 使用 preset-wind4、preset-attributify，尽可能采用属性样式；工程默认采用 `un-` 前缀避免组件 props 冲突。
- @ark-ui/vue 提供交互组件基础，平台封装统一视觉与表单体验；后台视觉不受状态页自定义影响。
- 支持简体中文/英文、浅色/深色、组织时区与个人显示时区、桌面优先响应式和现代浏览器。
- Go API 类型及路由为唯一契约来源，经 Huma 导出 OpenAPI，HeyAPI 生成类型、SDK、Pinia Colada 集成。管理 DTO 与匿名公共 DTO 分开，不依赖客户端隐藏秘密字段。
- 监控编辑器按类型呈现适用配置，高级选项渐进展开；编辑、诊断、失败原因与通知记录能定位到对应监控项和轮次。

## 身份与权限

内置账号，关闭公开注册，OIDC 不在首版范围。拟采用服务端会话及 Cookie 鉴权；角色和写操作授权由后端执行，秘密不回读明文，日志、导出、审计和公开接口统一限制敏感内容。

| 能力 | 管理员 | 操作员 | 只读 |
| --- | --- | --- | --- |
| 查看监控、诊断和服务器信息的脱敏结果 | 是 | 是 | 是 |
| 配置/暂停监控、手动检查、配置维护 | 是 | 是 | 否 |
| 管理状态页内容、发布、公告与分组 | 是 | 是 | 否 |
| 选择已有通知渠道与秘密引用 | 是 | 是 | 否 |
| 管理账号、秘密及通知渠道 | 是 | 否 | 否 |
| 管理 Beszel 凭据与系统设置 | 是 | 否 | 否 |

域名入口与反代可信设置作为拟采用的管理配置，由管理员提供；操作员可选择已配置入口发布页面。记录配置变更审计日志，不记录秘密原文。

## 监控与状态

首版类型为 HTTP(S)、TCP、DNS、被动心跳与证书到期；完整设置见 [配置清单](./monitor-options.md)。

- 主动可用性检查分检查轮次与探测尝试，默认追加重试 2 次、连续失败确认阈值 1、连续成功恢复阈值 1。
- 所有 HTTP 请求方法采用同一重试策略，不按 method 改变次数；请求的可重复探测性由配置者负责。
- 固定计划间隔、同项不重叠；每轮预算含所有尝试、等待和收尾，不超过检查间隔。重试次数是上限，展示实际尝试数与原因。
- 首次及缺少有效观测时为 Unknown；进程重启立即检查、不回放历史检查，采集断档不能当作 Up 或目标 Down。
- 被动心跳使用独立可轮换密钥、预期周期与宽限；初始等待 Unknown、超期 Down、成功上报 Up，并接受显式失败上报。
- 证书四态为有效、即将到期、已过期、检查失败；默认每日检查、30/14/7/1 天提醒阈值，可配置，不参与服务可用率。
- 暂停停止采集；维护继续采集、排除对应可用率时间并抑制故障/恢复通知。重叠时间按并集处理。

## 可用率与历史

可用率为确认后状态的 `Up / (Up + Down)`，不回溯确认时间。Unknown、暂停、维护排除分母；覆盖率为 `(Up + Down) / (窗口时长 - 暂停/维护并集时长)`，展示有效统计时长。没有有效统计数据时显示暂无统计，不能显示 100%。

默认留存可配置：原始轮次 14 天、尝试明细 3 天、5 分钟聚合 90 天、小时聚合及状态区间 13 个月。聚合保存时间权重及覆盖信息，不能把样本数比例冒充已确认的时长可用率。不默认保存完整请求/响应正文、秘密头或凭据。

## 通知

Shoutrrr 使用用户指定的 nicholas-fedor 项目，承担渠道协议适配。平台持久化逐渠道投递任务、结果及有限退避重试；允许极端情况下重复投递，跳过失去时效的故障消息。

确认故障与恢复各通知一次；初始 Up 不通知；持续故障提醒可配置且默认关闭。维护退出后有效评估当前状态：仍故障则通知，若此前已发故障且维护内恢复则补发恢复；Unknown 不补发。证书阈值与续期通知独立配置。持久任务、事件版本与通知规则协同防止过时消息覆盖当前状态。

## 公开状态页与自定义

- 多个匿名公开页面，各自选择监控项、公开别名、分组及排序；支持人工公告、事件进展和计划维护，受保护页面后续支持。
- 每页可配置标题、描述、Logo、品牌色、链接和深浅色；选择公开监控项及别名，设置分组和排序；总体状态与公告影响规则见 [发布规则](./status-page-policy.md)。
- 每页默认 `https://example.com/status1`，可绑定 `https://status1.example.com/`；两种入口指向同一页面配置和公共数据，首版同时支持。
- 独立域名由 DNS A/AAAA 或 CNAME 指向部署入口；反代提供该域名 HTTPS、保留 Host 并转发给同一 Go 服务。平台维护绑定，首版不自动修改 DNS 或申请证书。
- 页面直接由平台内置 Vue CSR 界面渲染，自定义配置只作用于该页面，保持后台界面固定。拟采用预览、保存草稿、显式发布流程，公开访问读取已发布配置。
- 公开字段使用白名单，不包含原始目标、凭据、请求配置和内部诊断，后台鉴权与 CSRF 校验继续独立执行。
- GitHub 主题、主题包安装/更新、任意主题脚本及 iframe 消息桥移出首版，见 [ADR 0011](./adr/0011-built-in-configurable-status-pages.md)。

## Beszel

管理后台提供独立服务器页，首版连接一个 Hub，展示服务器摘要、历史图表和容器列表。网站监控、可用率和通知判定不引用服务器指标；公开状态页首版不展示这些指标。

通过 Go 适配层读取专用账号可见数据，凭据不交给 SPA。标记来源、同步时间、失联和数据过期；历史展示尊重 Hub 实际数据和保留策略，不默认复制其全部历史。支持版本和认证兼容在实现阶段核实并固定。

## 实现与验收

确认后先建立工具链、双数据库迁移和 Huma/HeyAPI 生成流程，再实现身份、监控/统计、通知、状态页自定义与发布、Beszel 和完整前端。每个阶段形成可运行且可验证的结果。

必须验证：

- SQLite 与 PostgreSQL 的监控配置、状态转换、历史边界和投递恢复一致。
- 重试上限、超时预算、阈值、HTTP 各方法统一策略、心跳超期与证书四态。
- 进程停机、首次 Unknown、维护/暂停并集、零分母、覆盖率及精确跨窗口统计。
- 持久通知在重启、渠道失败、维护退出和状态更新后的有效性。
- 角色授权、秘密不回读、匿名公开 DTO、配置审计。
- `/status1` 与域名根路径访问同一页；页面子路由、资源和 API 地址正确；未知 Host/保留路径不会误路由。
- 不同状态页的品牌、内容、别名、分组、排序和深浅色独立，修改一页不会改变其他页或后台。
- 自定义预览、草稿、发布流程及桌面/移动布局可用；公开页面只读取已发布字段。
- Beszel 数据正常、失联、过期或版本不兼容均不改变网站状态。
- 前端类型检查、构建、必要交互验证，以及 100 项/30 秒容量目标压测。
