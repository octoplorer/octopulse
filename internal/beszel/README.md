# Beszel read-only adapter

Verified baseline: Beszel `v0.20.0`, commit [`a0dc19eacf6902d2f6934a3efd7ea7277198c40b`](https://github.com/henrygd/beszel/tree/a0dc19eacf6902d2f6934a3efd7ea7277198c40b). The adapter accepts the `0.20.x` release family and reports other versions explicitly. This boundary must be reviewed with the upstream schema before accepting another minor version.

- `/api/collections/users/auth-with-password` uses an ordinary Hub account; `/auth-refresh` renews an existing valid token. No superuser credentials or token reach the SPA. MFA/password-disabled accounts fail with a specific integration error.
- `/api/beszel/info` **requires authentication**, confirmed in the fixed [`api.go`](https://github.com/henrygd/beszel/blob/a0dc19eacf6902d2f6934a3efd7ea7277198c40b/internal/hub/api.go), and against the released Hub binary. The returned `v` identifies the Hub version.
- [`types.d.ts`](https://github.com/henrygd/beszel/blob/a0dc19eacf6902d2f6934a3efd7ea7277198c40b/internal/site/src/types.d.ts): systems use `info.cpu/mp/dp`; `system_stats` uses `created/stats`; containers use `name/image/status/cpu/memory/updated`. Container memory is the upstream MiB measurement, not a percentage. Network history uses `stats.b=[sent,received]` in bytes/second; older `ns/nr` values convert with `1,048,576`, matching upstream `agent/utils.BytesToMegabytes`.
- History resolutions match [`chartTimeData`](https://github.com/henrygd/beszel/blob/a0dc19eacf6902d2f6934a3efd7ea7277198c40b/internal/site/src/lib/utils.ts): 1h→1m, 12h→10m, 24h→20m, 1w→120m, 30d→480m. Requests include a validated system ID and server-side time/type filter. Full Hub history is not replicated.
- [`collections.go`](https://github.com/henrygd/beszel/blob/a0dc19eacf6902d2f6934a3efd7ea7277198c40b/internal/hub/collections.go) restricts data to systems associated with the authenticated user. An ordinary `readonly` account is supported and was used for the real Hub test.

Only the latest normalized systems snapshot is persisted. History and container caches are limited to 128 entries each; pagination caps each fetch at 5,000 records and a response at 4 MiB. Unavailable data remains explicitly stale; changing the Hub configuration invalidates snapshots and authentication. No Beszel operation creates uptime rounds, state intervals, events or delivery jobs.

Tests use an HTTP fixture matching the PocketBase contract for password authentication, token refresh, filtering, normalized units, stale cache, MFA, permissions and version errors. `OCTOPULSE_TEST_BESZEL_FIXTURE` enables an additional released-Hub integration test using a JSON fixture containing `url`, `email`, `password`, `system`. Keep the fixture outside the repository with mode `0600`. The real test authenticates a normal readonly account and verifies systems, history, containers and token refresh; seeded history/container records are fixtures and are not evidence of agent collection performance.
